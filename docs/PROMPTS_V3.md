# خارطة البرومتات V3 (تحل محل V2 وPROMPTS.md)

**الحالة:** ✅ نُفذ: Vite + TypeScript، ثم IndexedDB.
**القاعدة:** خطوة واحدة في كل جلسة، وتتحقق منها يدوياً قبل التالية.
**قبل أن تبدأ:** استبدل `docs/ARCHITECTURE.md` بالنسخة 2، وضع `SUPABASE.md` في `docs/`.

---

## البرومت التعريفي (في بداية كل جلسة)

```
أنا طالب ماستر أنظمة مدمجة، وأبني "خزانة الأفكار": منصة تحفظ أفكاري وتمنع تشتتي، ثم تحوّل الفكرة إلى نموذج أولي IoT يعمل (كود ESP32 + لوحة تحكم + قراءات حية) دون دورة Supabase/Vercel اليدوية.
اقرأ docs/ARCHITECTURE.md كاملاً (نسخة 2) وهو مرجع ملزم، وقراءة الكود الحالي.
لخّص لي في 5 أسطر: ما فهمته من المعمارية، وما الذي ينفذه الكود حالياً.
اعمل خطوة واحدة في كل مرة، اشرح قبل أن تعدّل، وطبّق "تعريف الإنجاز" في آخر الوثيقة.
```

---

## الخطوة 1: مواءمة الكود مع المعمارية (بلا تغيير في السلوك)

```
قارن بنية src/ الحالية بالقسم 5 من ARCHITECTURE.md وأعطني تقرير فجوات قصيراً، ثم نفّذ بعد موافقتي:
1. أنشئ core/: types (Idea مع schemaVersion وحقلي memory وlifecycle)، settings، ناقل أحداث typed، سجل وحدات حسب عقد AppModule، وcapabilities.ts كما في القسم 3.
2. انقل منطق الأفكار الحالي إلى modules/vault/ كوحدة مسجلة.
3. أضف feature flags في الإعدادات (كلها مغلقة ما عدا vault).
4. أنشئ docs/DECISIONS.md بأول قرارات: Vite بدل Next.js، IndexedDB أولاً، لا استيراد بين الوحدات، Managed قبل Export، ESP32 فقط في v1.
5. أضف قاعدة ESLint تمنع استيراد وحدة من وحدة أخرى.
لا تغيّر شكل الواجهة ولا السلوك، وتأكد أن بياناتي الحالية تعمل.
```

## الخطوة 2: Supabase والمزامنة

الصق برومت **SUPABASE.md** (القسم 3) كما هو، ثم أضف في نهايته:

```
أضف أيضاً:
- migration تضيف إلى ideas العمودين memory (text) وlifecycle (text) إن لم يكونا موجودين.
- كل رد LLM يُتحقق منه بـ zod مع إعادة محاولة واحدة، والمخططات في src/llm/schemas.ts.
- أنشئ llm-proxy كما وُصف، واجعل الواجهة تستخدمه افتراضياً.
```

## الخطوة 3: PWA والالتقاط السريع (الهاتف جزء أساسي من المنتج)

```
حوّله إلى PWA: manifest وservice worker وتثبيت وعمل دون إنترنت للقراءة والكتابة (عبر outbox).
أضف زراً عائماً "فكرة سريعة" يفتح شاشة تسجيل بالكتابة أو الإملاء الصوتي (SpeechRecognition عبر caps.speech، وإخفاؤه إن لم يُدعم) وتُحفظ كمسودة تُناقش لاحقاً.
حسّن واجهة الجوال: أهداف لمس 44px، وتنقل سفلي، وجداول تتحول إلى بطاقات.
```

## الخطوة 4: وضع التركيز

```
أنشئ داخل modules/vault/ صفحة "التركيز":
- مشروع نشط واحد بارز مع الخطوة التالية غير المكتملة وشريط تقدم.
- عند تعيين فكرة إلى doing وتجاوز maxDoing: نافذة تسألني أي مشروع أوقفه.
- حالة "تبريد" 7 أيام للأفكار الجديدة مع عدّاد، وزر "تجاوز" يتطلب كتابة سبب. أضف cooldown_until مع migration.
- شريط نسب الأفكار (ضمن تخصصي / تعلم جانبي / تشتيت).
```

## الخطوة 5: المساعد الواعي بالمشروع (قلب المنصة)

```
أنشئ src/llm/context.ts بدالة buildProjectContext(idea) ترجع نصاً ضمن ميزانية رموز قابلة للضبط، يضم بالترتيب: بطاقة الفكرة، الخطوات المنجزة والمتبقية، BOM، ملخص آخر نموذج أولي إن وُجد (اللوحة، التوصيل، مفاتيح اللوحة، revision)، حالة الجهاز إن وُجد، idea.memory، ملاحظاتي.
في تفاصيل الفكرة أضف زر "ناقش هذا المشروع" يفتح محادثة تبدأ بهذا السياق، وتحفظ المحادثة في idea.chat.
عند إغلاق الجلسة أو بعد N رسائل: استدعِ LLM لتحديث idea.memory بملخص قرارات وتغييرات مختصر (لا نسخ حرفي).
زر "عدّل الخطة" يعيد توليد الخطة مع الإبقاء على الخطوات المنجزة ويحفظ النسخة السابقة في plan_history.
اكتب اختبارات لـ buildProjectContext (الترتيب، احترام الميزانية، غياب البيانات الاختيارية).
```

## المرحلة IoT (كل وحدة خلف feature flag، بهذا الترتيب)

**الخطوة 6: النموذج الأولي (بلا رفع ولا أجهزة)**
```
أنشئ modules/iot/prototype/. عرّف مخطط zod لـ PrototypeV1 (القسم 8.2). 
تبويب "نموذج أولي" في تفاصيل الفكرة بزر "ولّد": يستخدم buildProjectContext وllm-proxy ويطلب PrototypeV1 فقط (ESP32 افتراضياً)، ويتحقق بـ zod، ويحفظ في idea_prototypes (migration + RLS + user_id) مع revision.
قالب البرمجيات إجباري: الكود لا يحوي أي واي فاي أو رمز مكتوب، بل يقرأ إعداداته من Preferences (NVS) ويرسل القراءات كل 5 ثوانٍ افتراضياً إلى عنوان الاستقبال، ويقرأ من الرد commands وfirmware.
اعرض: جدول التوصيل، الكود (Monaco تحميل كسول) للقراءة والنسخ، وقائمة warnings.
فاحص الأرجل بكود TypeScript حتمي مع اختبارات (أرجل مكررة، أرجل الإقلاع، أرجل الإدخال فقط).
زر "عدّل عبر النقاش" ينتج revision جديداً ويعرض الفروقات. لا رفع ولا ترجمة بعد.
```

**الخطوة 7: لوحة التحكم والمحاكي (تعمل على الهاتف)**
```
أنشئ modules/iot/dashboard/: مكوّن يرسم widgets من PrototypeV1.dashboard (gauge, line_chart, status_badge, toggle_switch, slider) بـ SVG/Canvas بلا مكتبة ثقيلة، متجاوب مع الجوال.
زر "محاكاة" يبث simulation.frames كل interval_ms، ويعمل بدون أي جهاز أو حاسوب. اختبارات للرسم من JSON.
```

**الخطوة 8: الاستقبال والأجهزة (Managed)**
```
Migrations لـ devices وdevice_tokens (token_hash sha256) وiot_telemetry وiot_commands مع user_id وRLS، وفهارس مناسبة لـ Realtime.
Edge Function ingest-telemetry حسب القسم 9: تحقق بالتجزئة، حد 4KB، حد معدل، قبول مفاتيح dashboard فقط، وتحديث last_seen_at. الرد: { commands: [], firmware: null } حالياً.
في الواجهة: زر "سجّل جهازاً" يعرض الرمز مرة واحدة، وحالة online/offline (أقل من 3 أضعاف الفاصل)، وتغذية اللوحة من Realtime بدل المحاكاة، مع تبديل واضح بينهما. دالة مجدولة تحذف القراءات الأقدم من 30 يوماً.
```

**الخطوة 9: الترجمة المحلية والتهيئة والرفع (حاسوب)**
```
scripts/compile-local: سكربت Node يغلف arduino-cli المثبّت عندي ويقدّم POST /compile على localhost ويرجع ملفات .bin. 
modules/iot/flash/ (يظهر فقط إن caps.webSerial): 
1. مراجعة إجبارية تعرض warnings ونتيجة فاحص الأرجل وتتطلب تأكيداً.
2. ترجمة عبر السكربت المحلي، ثم رفع بـ esptool-js.
3. تهيئة بعد الرفع: نافذة أدخل فيها الواي فاي، ثم يرسل المتصفح JSON للجهاز عبر Web Serial (واي فاي + رمز + عنوان الاستقبال) دون حفظ كلمة المرور في أي خادم. 
4. Serial Monitor داخل الواجهة.
التسليم: إن كان الجهاز بلا webSerial، زر "جاهز للرفع" يضبط lifecycle=ready_to_flash، ويظهر في الحاسوب بنفس الحساب. وعند أول قراءة حية يصبح lifecycle=online ويحتفل التطبيق بذلك.
بديل للهاتف: بوابة captive portal في القالب عند عدم وجود إعدادات.
```

**الخطوة 10: الأوامر العكسية**
```
اربط toggle_switch وslider بإدراج صف في iot_commands. عدّل ingest-telemetry ليرجع الأوامر غير المنفذة في الرد ويعلّمها منفذة بعد استلام تأكيد الجهاز في الطلب التالي. حدّث القالب لتنفيذها. أضف مهلة صلاحية للأمر.
```

**الخطوة 11: OTA (ESP32)**
```
جدول firmware_releases وStorage خاص مع sha256. اجعل الرد من ingest-telemetry يحمل firmware:{version,url,sha256} عند وجود إصدار أحدث، وحدّث القالب ليتحقق من sha256 قبل التثبيت ثم يعيد التشغيل. زر "حدّث لاسلكياً" (هاتف وحاسوب) يترجم محلياً عند توفر السكربت، أو يستخدم آخر .bin مرفوع. بلا OTA لأجهزة بلا إعدادات تهيئة.
```

**الخطوة 12: الاختبار الرأسي**
```
اكتب docs/E2E_CHECKLIST.md من القسم 12 في ARCHITECTURE.md (ESP32 + DHT22 + LED) وانفذه معي خطوة خطوة، وسجّل كل خطوة يدوية أو عائق خارج المنصة، وأصلحها. لا نعدّ الإصدار الأول ناجحاً قبل أن تتم الخطوات الخمس كلها دون تدخل خارجي.
```

## بعد الاختبار الرأسي (حسب حاجتك)

- BOM كجدول قابل للتعديل مع قائمة مشتريات موحدة وتصدير CSV.
- صفحة مهاراتي وترتيب الأفكار حسب القدرة على تنفيذها الآن.
- تصدير متقدم: PDF وZIP وقوالب برومت حسب النوع.
- اختبارات Vitest موسعة (ويفضل إضافتها تدريجياً مع كل خطوة أعلاه).
- وضع التصدير (SQL + لوحة مستقلة)، دعم Uno/Nano، خدمة الترجمة السحابية، Blockly، الفوترة.

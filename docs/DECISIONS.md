# سجل القرارات المعمارية (Architecture Decision Records)

## ADR-001: Vite + Vanilla TypeScript (PWA) مع Supabase لاحقاً
- **التاريخ:** 2026-11-24
- **القرار:** الإبقاء على Vite + Vanilla TypeScript دون أطر واجهات ثقيلة في النواة، مع تأجيل Supabase إلى مرحلة M2.
- **السبب:** تقليل تعقيد البناء وحجم الحزمة، والحفاظ على بساطة التشغيل دون إنترنت على الهاتف، مع تركيز الجهد على المسار الوظيفي.

## ADR-002: التخزين المحلي أولاً عبر IndexedDB + Schema Versioning
- **التاريخ:** 2026-11-24
- **القرار:** اعتماد واجهة `Store` فوق `IndexedDBStore` (مكتبة `idb`) مع حقل `schemaVersion` ودالة `migrate` وترحيل لمرة واحدة من `localStorage` (`ideavault.v1`).
- **السبب:** دعم العمل دون إنترنت بسعة تخزين أكبر وبنية جاهزة للمزامنة لاحقاً (`outbox`) دون فقدان بيانات النسخة الأولى.

## ADR-003: معمارية وحدات معزولة عبر `core/` وناقل أحداث وأعلام ميزات
- **التاريخ:** 2026-11-24
- **القرار:** فصل الأنواع والإعدادات والقدرات (`capabilities`) وسجل الوحدات وناقل الأحداث داخل `src/core/`، ونقل منطق الأفكار إلى `src/modules/vault/`، وتعطيل أعلام ميزات IoT والتركيز افتراضياً في M1 المبكر، مع فرض قاعدة ESLint تمنع استيراد أي وحدة من وحدة أخرى.
- **السبب:** منع التشابك بين `vault` ووحدات `iot/*`، وتسهيل تفعيل كل وحدة تدريجياً دون كسر النواة.

## ADR-004: التكيف حسب القدرات لا نوع الجهاز، وESP32 أولاً في وضع Managed
- **التاريخ:** 2026-11-24
- **القرار:** استخدام `caps` (`webSerial`, `speech`, `touch`, `standalone`) لتكييف الواجهة، وحصر دعم الإصدار الأول في ESP32 ووضع Managed (لوحة JSON + جدول telemetry عام).
- **السبب:** ضمان عمل الهاتف كمخطط ومحاكٍ وريموت، والحاسوب كطاولة رفع عبر USB، دون تشتت في دعم لوحات أو استضافات متعددة.
